### B1. 源码和依赖核对

### B2. Windows 本机构建

如果存在已授权、可使用的隔离 Windows x64 构建环境：

1. 使用明确记录的工具链完成构建。
2. 从精确 R1-C Rust 源码生成候选产物。
3. 记录完整构建命令、版本与文件 SHA256。
4. 尽可能执行两次独立干净构建，检查可复现性。
5. 如构建字节不同，调查差异来源并准确报告，不伪称确定性构建。
6. 在隔离路径安装候选产物，并使用真实 Windows Node 运行时完成加载验证。

至少运行：

- 原生模块真实加载及导出接口检查。
- Vexus 主要检索调用。
- RiverMemo 新旧查询输入兼容。
- 错误参数和异常结果。
- Rust / JS ABI 一致性。
- 默认加载器拒绝不可信、缺失或错误版本产物。
- 来源、哈希及构建收据检查。

**不得用 Wine、Linux 交叉编译、静态源码检查或历史 Windows 二进制替代 Windows 原生加载验收。**

### B3. 环境不可用时的处理

若当前施工环境没有授权的 Windows 本机环境：

- 完成全部不依赖 Windows 的源码核查和构建准备。

- 不修改默认 Loader 来绕过缺失产物。
- 将 `WINDOWS_NATIVE_VERIFICATION=BLOCKED`。
- 交付所需环境、准确命令和剩余验证范围。
