# MCP / ChatGPT 工具调用指南
本文件用于 VCP-APP 的 MCP 入口。工具是否存在、输入字段和权限要求，以当前会话实际提供的 MCP tool schema 为准。

## 选择入口
- 优先使用本次动作对应的专用工具。专用记忆工具的 owner/folder 和授权检查不能通过通用入口绕过。
- 不知道原生工具精确名称或当前状态时，使用 vcp_tool_resolve 查询能力、身份、可用状态和描述；返回说明不是参数 schema，也不建立授权。
- 精确名称已知、没有更合适的专用 MCP 工具且具体动作已获授权时，使用 vcp_call_tool。
- vcp_chat 运行完整 VCP 管线，可能执行工具、写入或安排任务；不能把它当作只读查询接口，也不继承专用记忆工具的权限预检。

## vcp_call_tool 示例
提交结构化参数：
{"tool_name":"SciCalculator","arguments":{"expression":"1+1"}}

- tool_name 位于 MCP 顶层；arguments 只放对应原生工具的业务参数，保留字段名大小写。
- arguments 的字段名只能包含 ASCII 字母、数字和下划线。嵌套对象或数组仍保持 JSON 结构，桥接层负责编码。
- arguments 禁止包含 tool_name、archery、ink、river、vref、__proto__。
- 不传入原生请求起止标记、中文起止分隔符或其 fuzzy/ESCAPE 变体。原生转义写文件示例不能搬进这个入口；需要写入被限制的内容时应使用另一个明确支持且获授权的文件编辑能力，不能编码伪装以绕过拒绝。
- 每次只选一个精确工具名和具体参数值；不能提交工具候选列表或枚举选项说明。

## 授权和结果
- 客户端与服务器工具操作不同机器；先确认身份、目标和用户授权，不自动换机器执行。
- 写入、命令执行、消息发送、定时任务和持久化记忆须满足其具体门禁。maid、folder 或知识库选择器不授予访问权限。
- HTTP 成功、任务接收或排队不等于动作完成；检查结构化结果及必要的状态查询。
- 被拒绝时不换到 vcp_call_tool、vcp_chat 或其他更宽入口重试。
- 超时、断线、空结果属于结果未知；有副作用的动作先查状态，不能盲目重放。
